# 统一保存与本机用户资料读取

## 目标

维护者点击一次「保存」，当前角色的基础资料、推荐弧盘、推荐卡带和主/副属性优先级一起持久化。用户版读取同一台电脑上管理端选择的项目资料库；保存之后，已打开的用户版能更新显示，不要求先推送 GitHub。

## 用户路径

1. 管理员在角色页修改资料和推荐属性。
2. 顶栏「保存」校验并原子写入所选 Git 工作副本。成功后清除该角色的本地暂存，并解除关闭保护；失败时保留编辑且明确报错。
3. 用户版通过只读的本机服务读取允许公开的知识 JS 和图片。它每隔数秒检查资料版本变化，刷新时保留角色、页面、标签和个人设置。
4. 多电脑同步仍由管理版拉取或推送私有 GitHub 完成。用户 EXE 不携带私有仓库凭据；只有接入公共 HTTPS 发布端后，用户才能跨设备联网更新。

## 数据边界

- 管理端修改只写入所选 Git 工作副本；用户本地持有角色、养成偏好等个人设置继续留在本机。
- 用户服务只读知识包与公开图片，不提供管理 API，不读取私有 JSON、Git 元数据、来源快照或项目脚本。
- 保存基础资料和推荐时保留同一角色上已有的其他扩展字段、图片路径及其他角色数据。
- 项目内容先保存到本机；GitHub 推送是另一项由管理员发起的同步操作。

## 验收条件

- 一次保存写入基础资料、弧盘/卡带选择和1–5优先级；关掉再打开后值不变。
- 保存发生服务/API错误时保留编辑状态，避免显示成功；后台版本不支持时在请求前提示更新。
- 用户版仅本机只读加载保存后的知识及图片，检查到新版本后刷新，同时不暴露管理内容或覆盖个人设置。
- 用户没有选定本机资料库时仍能使用 EXE 内置资料。
- 隔离临时工作副本验证真实 EXE 保存、重启读取、失败保护和访问隔离。

## 发布与限制

- 管理程序、用户程序和构建脚本从私有仓库维护；单机用户 EXE 不读取 GitHub 私有仓库。
- 首期的“自动更新”范围仅限同一台电脑上的管理资料库变化。公开 HTTPS 资料发布端和小程序数据端尚未接入。
- 当前覆盖文件记录 25 名角色中的 21 名推荐配置，其中20名含卡带属性。其余没有覆盖记录的角色保持原始图鉴默认值，不凭空生成推荐。
- 本计划所对应的代码和 EXE 保存/重启实测已完成；本次 GitHub 发布采用 `main` 单主干，不把生成 EXE 或临时分析目录纳入源代码提交。
