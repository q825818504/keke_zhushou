# 原生装备卸装与装配

2026-10-16：原生路线研发首版；不增加正式版本号，不发布到更新仓库。之后再研发界面输入路线。

## 已核实的基础

现有固定 Core 0.4.4 和配套已签名插件无需更换。组件清单声明 `equipment.execute.v1`，真实只读握手声明 `equipment`、`native_equipment_v1`，`equipment.status` 返回接口就绪。之前只开放读取是助手调用层的范围，不能由此断定二进制不能写装备。

对应协议依据：NTE Drive Calculator 提交 `0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1` 的 `src/integrations/nte_core.py`、`src/services/native_game_session.py`、`src/services/native_inventory_lease.py`。`core` 是空幕/卡带，`module` 是驱动块。角色必须使用快照中的实例 UID（slot/serial），不能使用角色图鉴 ID 代替。

## 本次功能

读取数据 → DLL 原生读取 → 原生装备管理。卸装支持单个角色或全部已装备角色；装配支持选择目标角色、具体空幕与驱动实例、自动计算摆法或手动坐标、预览清单并确认执行。

单件操作开放 `equipment.unequip_module`、`equipment.unequip_core`、`equipment.equip_module`、`equipment.equip_core`；含空幕和驱动的已保存方案使用 `equipment.equip_one_key` 一次提交。页面不能指定任意 RPC 或游戏 UID。跨角色转移在预览中明确列出，完成后对所有装备状态整体核验。

自动摆放仅复用现有 DriveLayoutSolver，不与角色图鉴联动。内置最小静态目录包含12种实际形状与25个角色终端，后端独立校验越界、重叠和容量。界面坐标是形状包围盒左上角，原生接口使用原始形状锚点，通过目录偏移双向转换；竖4的界面(2,2)对应原生(3,2)。

预览绑定账号标签、当前提供方/对象域/PID、角色与装备实例、完整装备状态；两分钟内单次有效。执行前重新读取并比较，游戏换号、物品变化或实例变化时停止。原生读取、组件部署、扫描和卸装互斥。

单件操作仍串行派发并在每步后核验。保存方案若同时包含空幕和驱动，则通过与 NTE Drive Calculator 同版的 `equipment.equip_one_key` 一次提交整套位置，降低逐件刷新造成的游戏卡顿；执行前核对当前修订号，提交后等待装备快照更新并整体比较预览前后的全部装备状态。响应接受不代表成功；响应丢失但最终快照符合方案时记录成功，否则标记未确认且绝不自动重发。批量提交无法中断，停止按钮在提交前可阻止操作，提交后只等待核验。没有空幕的驱动方案和拆卸继续逐件执行。

操作前将原快照与计划备份到本机 `player-inventory/equipment-operations/`；备份失败不派发。记录当前在途指令、逐件核验与结束状态；未确认操作不会自动恢复执行。已确认的装备快照更新到用户明确选择的本机账号标签，其他类别及OCR批次保留。

## 验收边界

23项本地协议/故障测试、11项原库存回归及1380/900宽浏览器交互检查通过。用户分别授权真实测试「零」1件空幕和4块驱动；两轮全部由新快照核验成功。总库存6→6，仅这5件目标的装备/归属/位置字段改变，其他字段相同。原生路线已获真实卸装证据。

装配补充21项协议/失败路径测试、12形状及300个角色/形状位置检查，并通过独立装配页面浏览器回归。跨角色转移只在自有模拟库存中验证。

经用户授权，实机将此前从「零」卸下的同一件「失落光芒」空幕及4块驱动装回：首次3步确认后长条坐标未生效即停止；修正形状锚点转换后，仅执行剩余2步，全部确认。最终背包6→6，目标5件全部装备，12格物理位置与批准方案一致，所有其他字段和其他角色不变。再次预览为0步，无写入。证据保存在本机规划目录 live-assembly-verification.json 和 live-final-assembly-noop.json。

仅重建本地v1.5测试包，不发布、不推送、不修改正式v1.4安装器。鼠标/手柄路线仍待后续研发。

## 角色配装页与复用入口（2026-10-16）

读取数据页只执行DLL原生同步。成功读取时按本机账号保存装备快照和进程来源标记。角色配装页不另发游戏读取请求：装配和卸装预览使用该账号的快照；执行启动时再连游戏并以新快照完整比较，来源、实例或装备状态变化时拒绝执行。已过期旧快照会提示重新读取。

装备操作仍由 `InventoryService.equipment` 提供受限检查、预览、执行和取消入口，供后续计算配装方案调用。用户确认计算方案稍后开发，游戏配装目前只显示无已保存方案的空状态；不从角色图鉴取方案，也不读取计算器。

延迟优化去掉每条装备指令前的一次全量背包重读：第一条写入前仍完整核对，后续写入前核对原生进程来源及干净、未变化的库存修订；不支持修订号时回退完整核对。每条装卸命令后仍完整读取并比较目标状态与其他装备，未确认不重发。
