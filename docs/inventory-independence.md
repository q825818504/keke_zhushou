# 库存同步自主化路线（2026-10-07）

## 已完成：数据与采集分离

可可助手拥有根格式 schema_version=2，业务字段在 inventory 中，每类 contract_version=1。
装备记录使用稳定 instance_id、definition_id、category（drive/tape/other）、形状、格数、等级、属性及 is_equipped/is_locked/is_discarded。角色记录使用 character_id、等级、突破、觉醒、技能、弧盘与逐字段观察时间。None 表示尚未观测，不能当作0或false。

source 记录采集器及会话/快照/修订；coverage 分别描述集合完成与账号完整范围。只有集合完成且实例唯一的装备快照才能替换旧库存。角色与装备的真实账号归属仍由用户指定标签，不能从进程或会话标识推断。

读取旧版文件时在内存映射自有格式，不自动改写用户文件；下次成功同步按类别保存新版，并保留上一份文件。domains 保留上游原始数据，便于对照与完整导出。来源替换且不提供原始数据时清除对应旧原始域，避免误认来源。items/team/environment 的专用业务建模尚未完成，当前保留通用记录与原始数据。

InventoryService 只管理任务、契约验证、账号隔离与原子保存。CaptureAdapter 提供 prepare/open/read/abort/close；NteAdapter 独立负责原版路径、哈希、Core、游戏管道、分页、会话检查、中文名称和原字段映射。前端仅使用 inventory，不依赖 module/core/uid 等上游字段。测试中的独立采集器不启动 Core，也不使用上游原始字段；它只证明替换接口有效，不证明自主游戏采集已经实现。

## 已查明：自主采集所缺材料

调查基准为公开仓库提交 0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1。

- [项目声明](https://github.com/hxwd94666/NTE-Drive-Calculator/blob/0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1/RESPONSIBLE_USE.md) 明确 DLL、采集 Core 与计算/分析 Core 的实现暂按私有源码管理，并提供维护者合作入口。
- [采集组件来源](https://github.com/hxwd94666/NTE-Drive-Calculator/blob/0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1/third_party/native-capture/capture/SOURCE.md) 和 [Core来源](https://github.com/hxwd94666/NTE-Drive-Calculator/blob/0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1/third_party/native-capture/core/SOURCE.md) 均说明仅基础提交不能复现当前二进制，另有修改后工作树输入。
- 2026-10-07 GitHub API确认计算器仓库公开；其声明的 kongbaiz/UETools-NTE 源仓库以未认证公开访问返回404。此结果表示当前不能公开读取，不能推断仓库永久不存在。
- 公开计算代码片段不能替代采集器。现有材料尚未验证可独立构建的完整游戏采集源码，也未验证能直接替代它的官方库存接口。

复制 nte-core.exe/DLL 到可可助手安装目录仍属于上游二进制依赖。当前用户版不打包这些文件，也未修改游戏目录。

## 接下来逐步执行

1. 取得可独立构建的采集实现或足够的官方/授权接口资料。优先评估上游合作源码及其构建、修改、分发条件；同时评估游戏是否提供用户导出能力。尚未向任何维护者发送消息。
2. 做最小装备只读采集原型：稳定实例身份、驱动/卡带类别、装备角色、分页/变化证明、取消与释放连接。接入新的 CaptureAdapter，现有原版适配器用作对照。
3. 同步角色等级、突破、觉醒、技能与弧盘，保留未知状态；再扩展材料、队伍和环境各自可证明的采集范围。
4. 在同一游戏状态下对照总量、分类、已装备和角色，并逐实例核对；测试切号、换装、数量变化、超时、退出游戏、取消和缺页。已有1431/604/827/122/20是历史基准，游戏数据变动后不能强行匹配旧数字。
5. 可可助手自行管理组件准备、版本校验、启动/停止和更新；在原版未安装、无其目录、无其进程的环境完成安装与采集验收，再形成独立发行版。

## 采集来源必须满足的交付条件

- 完整源码或可维护接口、依赖及可复现Windows构建说明，说明游戏版本兼容范围。
- 稳定装备/角色身份及字段语义；全集、已观测容器、局部角色信息分别明确。
- 快照冻结、分页完整性、修订/会话身份及装备引用一致性。
- 仅读取账号资料；组件准备/卸载可管理，断开后释放本客户端资源。
- 名称/静态定义来源也可独立取得；当前中文名称仍可能依赖原版game_static.sqlite3。
- 源码和各依赖的使用、修改、分发条件逐项明确。

阶段19已经建立替换基础；阶段20已完成当前公开来源调查和验收定义；阶段21自主游戏采集与独立发行尚未实现，取决于可维护来源。

## 优先补充：真实账号身份（2026-10-07）

用户要求每次读取自动识别账号，失败类别仅保留该账号自己的旧快照。现有账号标签分文件已支持同电脑多账号，但同一标签不会自动检测切号。公开Core协议定义与真实归档未找到稳定游戏账号ID；归档中的account是用户指定标签。上游AccountManager.create_account依据本地名称生成ID，也不能作为游戏身份来源。

自主采集前置验收：必须读取经验证的玩家UID及身份作用域（区服/渠道等由游戏实际唯一性决定），明确其来源和有效时间。先确定账号主键，再加载该账号旧库存和累计角色。昵称仅为显示备注，重名或改名不能影响归属；识别不到时不能将数据合并进上次账号。同步期间身份变化即停止，后续另开新账号任务。同一UID重新登录仍归同一账号；不同UID即便昵称一致也隔离。PID、providerId、snapshotId、角色目录ID、装备UID及背包内容相似度均不得替代账号UID。

旧标签数据没有真实身份，不能按猜测自动归属到新识别的UID；保留为未绑定历史数据，身份确认后再迁移。当前尚未实现自动游戏身份识别，本次仅核实来源限制并调整路线，不改写玩家库存。图中0装备与20累计角色不足以证明当前账号身份或本轮角色覆盖。
