# 背包数据与读取数据

## 本轮结果

可可助手后台直接启动内置nte-core.exe，不再要求NTE计算器安装目录。原生组件仍属于作者的第三方实现，未独立重写游戏内Reader。

固定版本Core0.4.4 / native-plugins-v3，包含d3d12宿主、User/Combat/HUD/Performance插件及四份签名。宿主成套验证需要这些文件；助手只调用原有只读库存/角色/物品/队伍/环境接口，不启用战报或装备修改。

## 组件使用

读取数据 → 采集方式选择“DLL 原生读取” → 环境检测与组件部署 → 检测环境。游戏运行时尝试以有限查询权限获取HTGame.exe目录，也可填写程序路径或所在文件夹。环境检查区分：内置文件校验、游戏部署匹配、CRT运行库文件、游戏进程、原生命名管道。端点出现不代替协议与实际数据验收。

首次准备需要退出游戏，再点击一键部署组件，然后通过原游戏启动器重新启动并登录。部署只写固定清单中的九个文件；签名插件先写，d3d12宿主最后写。运行中拒绝部署/移除，不覆盖未知文件。文件写入失败时回滚新增文件；如果游戏途中启动，保留部署记录等待退出后清理。

移除只处理可可助手记录中本次新增且哈希仍匹配的文件，保留部署前已有文件。不同版本组件/其他模组冲突需先由用户处理，助手不自动删除。游戏目录不可写时需要以管理员身份运行助手。

SDK不是用户需要安装的开发环境，相关能力在游戏插件内。检查VC++ x64的vcruntime140.dll、vcruntime140_1.dll、msvcp140.dll存在性；存在性检查不保证每个ABI版本可用，真实同步仍做握手与读取验证。缺失时提供Microsoft官方安装入口，不捆绑开发SDK或自动静默安装。
官方资料：https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170

## 统一数据来源

原生数据仍在player-inventory中，截图原图及OCR批次仍在vision-scans中。账号数据API组合两者的视图，不重复写入截图，也不生成第二份会与纠错不同步的OCR数据。

同账号标签下可选原生库存或任一OCR批次；默认优先原生，否则优先完整扫描。没有完整数据时可查看部分识别结果。完整性只针对当前筛选列表，不把离线、NEW、停止后的部分批次称作背包全集。

相同词条的两件装备保留为两个扫描记录，OCR实例ID仅在批次内有效。没有游戏正式UID时不按词条跨来源合并或相加，否则会误删真实重复装备或重复计数。OCR没有读到已装备、锁定、弃置状态时保留未知，已装备总数显示—。角色/材料/队伍/环境仍展示其各自原生来源，不把装备截图中的角色名称候选当作完整角色养成快照。

背包数据集中显示统计、装备明细、已保存的数据来源和导出；点击“读取新数据”携带当前账号标签进入读取数据。读取数据的采集方式可选DLL原生读取、截图导入、鼠标全量、NEW增量或手柄全量，并在下方切换对应表单。扫描批次自动出现在背包来源列表，纠错在背包装备详情中保存，立即反映到账号视图；截图证据、历史扫描和失败重试仍位于读取数据。手动账号标签机制沿用现状，自动识别游戏UID仍待实现。

## 构建与验证

构建资源位于忽略的build/native-components，不把作者二进制提交进源码仓库。开发构建时通过scripts/prepare_native_components.py导入已匹配的包，然后desktop/build.py校验和内置。用户发行物运行不读取开发者的计算器目录。

来源与许可见desktop/native/NOTICE.md以及随包保留的licenses/native-capture。SOURCE明确说明修改构建不能仅由base commit复现。本轮是用户本机私有预览；外部分发前需要取得匹配对应源码或相应分发授权，不把现有源链接当作已满足所有对应源码要求。

验证：9项新增事务/来源/HTTP回归，11项原生协议和15项OCR回归；Chrome账号与扫描界面通过。Core在空工作目录独立启动版本自检通过。

真实只读联调使用build中的Core和游戏已加载组件，五类成功：1431装备、20角色、1754物品材料、1队伍、13环境。原始account_complete未知状态保留。报告build/native-integrated-live-report.json，结果仅写build/native-integrated-live；未修改正式账号或游戏目录。

尚需验收：完全不启动原计算器、由可可助手首次部署、通过原启动器启动游戏后同步的完整流程。当前游戏已有匹配部署，不能用现有端点成功来替代这项首次流程验收。

## 已保存数据的删除与覆盖

背包数据的来源选择旁可删除当前选中数据，首次点击显示确认按钮，第二次确认才删除。自动选择时删除实际显示的来源。原生来源删除该标签的五类快照及回退备份；OCR来源只删除所选批次的batch.json和图片目录，其他批次及账号不受影响。读取或识别进行中禁止删除。

同标签DLL原生读取按类别更新已有快照，失败类别保留原有值；截图导入、鼠标、NEW和手柄扫描每次创建独立批次，不覆盖原生数据或其他批次。重试和纠错继续更新原批次。
