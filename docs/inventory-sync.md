# 账号数据同步接入说明

本次实现集中于 Windows 用户端的“账号数据”，暂不做单件鉴定、装备操作或库存配装计算。用户入口、数据适配和本机存储已实现，已完成本机真实游戏的五类读取、分页校验及保存。

## 已接入的数据

| 分类 | 读取方式 | 保存范围 |
|---|---|---|
| 装备库存 | inventory 正式业务投影 | 稳定 UID、属性、形状、套装及组件实际提供的全部字段、装备角色引用 |
| 角色养成 | character 正式业务投影 | 等级、突破、觉醒、技能、弧盘等已观测字段；缺失或 null 不清空旧有效观测 |
| 全部物品与材料 | 独立 all_items 原始分页 | 所有已观测 InventoryContainerMap 容器；原始物品结构与数量，不猜测缺失数量 |
| 当前队伍 | team 原始分页 | 原始队伍快照，非攻略模板 |
| 当前环境 | environment 原始分页 | 当前组件提供的环境字段 |

所有分页字段和快照诊断一并保存，可导出 JSON。页面暂用可搜索、分页、可展开的记录列表；装备和角色优先使用计算器静态图鉴中的中文名称；材料、队伍与环境仍保留原始字段，尚未完成所有ID的中文展示。没有将玩家数据写入攻略或知识文件，也没有自动覆盖已有配队持有设置。

## 使用

1. 使用本文对应的用户预览 EXE：`dist/windows/inventory-preview/KekeAssistant.exe`。关闭此前的可可助手用户窗口后，再打开新版；两个版本共享单实例标识。
2. 准备 NTE 计算器完整安装目录，或完整源码/组件目录。适配固定提交 `0e7a6b4e8e61d7a288e520bbc192a411d68c2fb1`，原生 Core 0.4.4，SHA-256 为 `1f875858409ad47eed83ded7991d7a3133eb4afafebf2c2b09cd52802c7b2fed`。
3. 在原版计算器内启用原生同步对应的中风险模式，完成游戏组件准备，启动并登录游戏。关闭计算器的同步会话，避免两端同时占用游戏采集管道。可可助手本轮不安装游戏 DLL，也不启动 Loader。
4. 可可助手侧栏进入“账号数据”，填写计算器目录和本机账号标签，点击“同步所有数据”。支持源码目录内的 `third_party/native-capture/component-bundle.json` 、安装目录内的 `component-bundle.json` 及 PyInstaller 安装目录的 `_internal/component-bundle.json`（自动识别）。
5. 切换游戏账号时先取消任务，修改本机账号标签，再同步。标签由用户指定，不宣称已识别游戏账号 ID。
6. 浏览各类数据，或点击“导出完整数据”备份。

如果只有原版单文件 EXE、没有可读取的组件目录，需要先取得其完整安装/源码组件目录。此前用于研究的 `public-source` 只含文本，**没有可运行 Core/DLL**，不能将该研究目录当作完整组件包使用。

## 存储与失败行为

- 玩家文件存放于 `%LOCALAPPDATA%/KekeAssistant/player-inventory/`，独立于 Git 仓库和管理端公共资料。
- 按本机账号标签哈希分文件。每个类别成功后以临时文件原子替换；上一版保存在 `.previous.json`，写失败保留原文件。
- 类别分别提交，某类别失败不抹去已保存内容；界面保留每类保存时间、来源与错误。不同类别可能来自不同时间，不能当作一份同时观测的完整账号快照。
- 角色累计观测保留逐字段时间；明确已观测的空觉醒选择可清空，未初始化的空列表不可清空；技能字段逐项合并。原始观察页面不改写。
- 完整装备须满足集合完成、业务投影完成、UID 唯一、角色装备引用被覆盖；分页身份、游标、数量、64MB限制及读取末尾来源修订校验。
- “全部物品”仅声明客户端已观测容器完整，保留 `complete=false` 和账号覆盖未知；不保证服务器全部账号数据。
- 退出时取消任务并关闭本程序启动的 Core，不关闭游戏、不清理游戏组件。

## 实现与验证

- `inventory_sync.js`：用户板块；`desktop/inventory/`：独立编写的公开协议适配、任务与存储。
- `desktop/runtime.py`：loopback接口，仅提供固定同步动作；Host、Origin与随机请求令牌校验，不把任意 RPC 暴露给网页。
- 上游参考：https://github.com/hxwd94666/NTE-Drive-Calculator 。本次没有复制其 Python 实现代码，也没有在用户发行包内再分发其 Core/DLL。
- 已运行8项协议/服务回归、真实 Chromium 页面操作和实际用户EXE冒烟，并成功完成用户本机真实游戏的五类同步。原始物品优先显示Core提供的displayName和Amount，装备优先显示names.zh_cn；这不证明服务端账号全部数据已读到。

后续优化记录列表与属性展示，再将标准化 UID 库存交给既有驱动拼图求解接口。暂不扩大到单件鉴定。

## 本机预检结果

用户提供的 `C:/Program Files/NTE Drive Calc` 已核对；其 `_internal/nte-core.exe` SHA-256 与固定版本完全匹配，静态数据文件存在。初次检查原版mode=low、当前游戏原生管道未就绪；由用户在原版启用原生模式并重启游戏，可可助手没有注入或部署组件。

实机联调经过：先排除不属于当前游戏的旧管道；用户完成原生准备后存在连接超时，退出原版释放会话后读取成功。实际保存装备1431件、角色养成20条、全部已观测物品1753条、队伍1条、环境13条，均通过对应完整性检查。验证后的快照已写入可可助手正式本机玩家存储。

## 首页背包统计

首页显示背包总数、驱动块数量、卡带数量、已装备数量和角色数量。前三类及已装备使用同一份装备快照：module为驱动块，core为卡带，equipped=true为已装备子集。角色数量使用该账号已同步角色记录，不用公共角色目录条数。点击卡片筛选对应明细；物品材料、队伍与环境收纳到“其他同步数据”，不再作为首页统计卡片。无快照显示—，已保存空快照显示0。

## 自主化第一阶段

业务库存现已采用schema_version=2的自有契约，前端按category=drive/tape与is_equipped统计。旧字段仅在NTE适配器中映射；旧文件内存兼容读取，原文件不改写。已新增独立采集替身、无损迁移和会话变化回归。自主采集和独立组件发行仍未实现，详见 [自主化路线](inventory-independence.md)。
